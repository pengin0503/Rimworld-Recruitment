# 入植者募集MOD 設計仕様

- 対象: RimWorld 1.7（1.7.4985 で確認、.NET 10 / Waylith ランタイム）
- 言語: C#（net10.0）
- 前提MOD: Harmony（`brrainz.harmony`）。使うのは、キャラバン出発時の警告と、通信機の通信先への追加の2か所だけ。
- packageId: `pengin0503.recruitment`

## 1. 目的

戦闘などで失った入植者を、費用と時間を払う「募集」で継続的に補充できるようにする。

## 2. 募集方式

方式は XML の `Recruitment.RecruitmentMethodDef` で定義する。研究条件・費用・期間は Def の値が初期値で、費用と期間は MOD 設定で上書きできる。

| 方式 | 費用（初期値） | 期間（初期値） | 必要研究 | 開始場所 | 到着 | 使える場所 |
|---|---|---|---|---|---|---|
| キャラバンで募集 | 50 | 6〜10日 | なし | 来訪中の商人を右クリック | 徒歩（マップ端） | 地上 |
| 拠点で募集を依頼（使者） | 100 | 依頼後4〜7日 | なし | キャラバンで拠点を訪ねる | 徒歩（マップ端） | 地上 |
| 無線放送 | 250 | 3〜5日 | `MicroelectronicsBasics` | 通信機の通信先「入植者募集を呼びかける」 | 徒歩（マップ端） | 地上 |
| 軌道通信 | 600 | 1〜3日 | `ShipComputerCore` | 同上 | 輸送ポッドで降下 | 地上・宇宙 |

- 「宇宙」とは `map.Tile.LayerDef.isSpace` が真のマップを指す（Odyssey）。
- 期間は [最小, 最大] 日の一様乱数。使者の場合は、依頼が成立してから応募者が入植地に着くまでの日数。キャラバンの移動にかかる日数は含まない。
- 費用の支払い元:
  - キャラバン・無線放送・軌道通信: 開始時に、そのマップのシルバーから支払う。対象は、禁止されておらず、倉庫内または居住エリア内にあるもの。
  - 使者: 依頼が成立したときに、キャラバンの持ち物のシルバーから支払う。
- 応募者が0人なら募集失敗。費用は返さない。
- 費用が設定額（初期値200シルバー）以上の方式は、開始前に、費用・期間・到着方法の確認を出す。額を0にすると常に確認し、設定をオフにすると確認しない。通信機の方式では、確認は交渉画面の中の次のページとして出す。

### 2.1 開始操作

- **キャラバンで募集**: 入植者で商人を右クリック →「入植者の募集を依頼」。入植者が商人のところへ行って話した時点で開始する。商人に対して交易可能（`Pawn.CanTradeWith(faction, traderKind)` が許可）であることが条件。商人が立ち去るなどして中断したら、その旨を表示する。
- **無線放送・軌道通信**:
  - Harmony で `Building_CommsConsole.GetCommTargets` に通信先 `RecruitmentCommTarget`（`ICommunicable`）を1つ追加する。通信機の右クリックメニュー（バニラの通信先一覧）に「入植者募集を呼びかける」が並ぶ。
  - 選ぶと、バニラの `UseCommsConsole` ジョブで入植者が通信機を使い、派閥との交渉と同じ `Dialog_Negotiation` が開く。そこで、無線放送と軌道通信のどちらにするかを、費用・期間を見て選ぶ。使えない方式は、理由付きで無効になる。
  - 通信機が使えない理由（停電・電力なし・会話不能）は、バニラがまとめて表示する。
  - `RecruitmentCommTarget` はゲームに1つで、`GameComponent_Recruitment` が Deep 保存する。ジョブは通信先を参照で保存するため。
- **使者（拠点で募集を依頼）**:
  - 入植者でキャラバンを編成する（バニラの操作）。
  - ワールドマップでキャラバンを選択し、拠点を右クリックして「拠点で募集を依頼」を選ぶと、キャラバンがそこへ向かう（到着時アクション `CaravanArrivalAction_RequestRecruitment`）。
  - すでにその拠点を訪問中のキャラバンには、「入植者の募集を依頼」ボタンを出す（バニラの交易ボタンと同じ種類）。
  - 拠点の定義（`WorldObjectDef` の `Settlement`）に、XML パッチで `WorldObjectComp_RecruitmentRequest` を追加して実現する。`ParentName="Settlement"` で継承する MOD の拠点にも付く。
  - 到着時アクションの `StillValid` は、キャラバンの移動中に毎回呼ばれる。条件が崩れるとキャラバンが止まってしまうため、拠点側の軽い条件（存在する・敵対していない）だけにする。シルバー・再依頼の待ち時間・同時募集数は、到着時に確認する。満たさなければ、理由をメッセージで出す。

### 2.2 使者の条件と社交補正

- **依頼できる拠点**:
  - 地上の拠点であること。
  - 地図化（攻撃など）されていないこと。
  - プレイヤー以外の派閥で、敵対していないこと。
  - その派閥が応募者を出せること（3. の条件。許可の条件は除く）。
  - 再依頼の待ち時間が過ぎていること。
- **交渉役**: キャラバン内の交渉役（`BestCaravanPawnUtility.FindBestNegotiator`）。その派閥と取引できる人に限られる。帝国の拠点は、交易と同じく爵位の許可（バニラではナイト以上）が必要。
- **社交の効果**: 交渉役の社交スキル s（0〜20）に対して、0人になる確率 P0 = clamp(0.35 − 0.015 × s, 0, 1)。残り (1 − P0) を、1〜3人の設定上の重みの比で配分する。係数は MOD 設定で変えられる。期間には影響しない。
- **再依頼の待ち時間**: 同じ拠点には、依頼してから一定期間は依頼できない。初期値は15日で、MOD 設定で変えられる。拠点の ID ごとに最後の依頼時刻を保存する。
- **シルバーの警告**:
  - **出発時**: Harmony で `Dialog_FormCaravan.TrySend` にプレフィックスを足す。キャラバンの行き先が「依頼できる拠点」で、持たせるシルバー（積み荷＋出発する入植者の所持品）が費用に足りなければ、確認画面を出す。了承すれば、そのまま出発する（バニラの食料などの警告はその後に出る）。
  - **移動中**: 依頼に向かうキャラバン（到着時アクションが依頼）のシルバーが費用を下回ったら、通常の重要度の警告（`Alert_EnvoyCaravanShortOfSilver`）を出す。
  - **行き先を選ぶとき**: シルバーが足りなければ、右クリックメニューの項目が理由付きで無効になる。
- キャラバンのメンバーは普通のワールドポーン（状態がキャラバンのメンバー）なので、移籍しない。思考・加齢・欲求・入植者バーへの表示は、すべてバニラのまま扱われる。

## 3. 応募者

- 人数は募集開始時に 0〜3 から抽選する。初期値は各25%で、重みは MOD 設定で変えられる。使者は 2.2 の式に従う。最大人数（3人）は固定。
- 人数・到着予定 tick・出身派閥は開始時に確定し、セーブデータに保存する。ポーン本体は到着時に生成する。
- **出身派閥**:
  - キャラバンで募集: 商人の派閥。
  - 使者: 依頼した拠点の派閥。
  - 無線放送・軌道通信: 条件を満たす派閥から一様に抽選する。
  - 条件:
    - プレイヤー派閥でない。
    - 非表示でない。
    - 壊滅・非活性でない。
    - 一時派閥でない。
    - `humanlikeFaction` が真。
    - `permanentEnemy` でない（MOD 設定で含めることができる）。
    - 交易に許可（permit）が必要な派閥（帝国など）の場合は、プレイヤーの入植者の誰かがその派閥のキャラバン交易の許可を持っている（バニラ環境ではナイト以上と同じ）。
  - 許可（爵位）の条件は開始時にだけ確認する。募集中に爵位を失っても、その募集は続く。
  - 到着時にその派閥が許可以外の条件を満たさなくなっていたら、許可の条件も含めて抽選し直す（新しく選ぶ派閥なので、開始時と同じ条件にする）。候補がなければ、派閥なし（バニラの放浪者と同じ `Villager`）で生成する。
- **生成方法**:
  - `faction.def.basicMemberKind`（なければ `Villager`）を、その派閥の一員として生成する。
  - 種族・ゼノタイプ・思想・経歴は、派閥の設定に従う。
  - 爵位は付けない（`forbidAnyTitle`）。
  - 成人のみ。MOD 設定で子供を許可し、ストーリーテラーも子供を許可している場合は、子供も含む。
- 加入するときに `SetFaction(Faction.OfPlayer)` を呼ぶ。

## 4. 到着と加入

- **到着先**:
  - 募集を結び付けたマップ（使者の場合は、依頼時に選んだ拠点マップ）が、プレイヤーの拠点で、かつ方式の使える場所（地上・宇宙）に合っていればそこにする。
  - 合っていなければ、条件に合うプレイヤー拠点マップのうち、自由な入植者が最も多いものにする。
  - 候補がなければ募集失敗。ただし、グラヴシップが飛行中（`Find.CurrentGravship != null`）なら、失敗にせず着陸まで保留する。
  - 返却するシルバーは、元のマップが消えていれば、残っている拠点マップに置く。
- **判断待ちの応募者の保持**: 判断待ちの応募者（プレイヤー以外の派閥）は、`GameComponent_Recruitment` の `ThingOwner<Pawn>` に保持する（Deep 保存）。ワールドポーンにすると GC で破棄されうるため。
- **戻す処理**: 保持していたポーンを戻すときは、到着方式が失敗しても `GenPlace` で直接置く。それでも置けなければ保持し直し、あとで再試行する。どの判断待ちからも参照されていない保持ポーン（ロード時に Def が欠けた場合など）は、プレイヤー派閥なら拠点に戻し、それ以外は破棄する。加入する応募者には、念のため、削除済みのポリシー・思想を整える処理を通す。
- **到着方法**:
  - 方式ごとの `PawnsArrivalModeDef` 候補を順に試す。徒歩は `EdgeWalkIn`、軌道通信は `CenterDrop` → `EdgeDrop` → `RandomDrop`。
  - どれもそのマップで使えなければ、`canBeBackup` の方式を使う（バニラの `QuestPart_PawnsArrive` と同じ）。
- **加入方式**（MOD 設定）:
  - **受け入れ選択（初期値）**:
    - 到着時に応募者を生成してレターを送る。レターから専用画面を開き、各応募者を採用・拒否して確定する。
    - 判断期限は24時間（ゲーム内時間、設定で変更可）。期限は毎 tick 確認する。
    - 期限までに確定しなければ全員拒否として扱う。
    - 拒否された応募者は、バニラの拒否時と同じ思考（`DeniedJoining`）を与えたうえで破棄する。
  - **自動加入**: 到着時に全員が加入する。

## 5. 同時募集

マップごとに、進行中の募集の上限を設ける。初期値は1件で、設定で変えられる。使者の依頼は、依頼時に選んだ到着先マップで数える。到着した時点で上限から外れる（判断待ちは数えない）。

## 6. UI

- **メインタブ「募集」**:
  - 進行中の募集（方式、到着先、出身派閥、到着までの日数）と、判断待ちの応募者（「確認する」ボタン）を表示する。
  - 各方式の開始方法の案内を表示する。
  - 開発者モードでは、確定済みの人数の表示と「即時到着」ボタンを出す。
- **応募者選択画面**（同じ判断待ちに対しては1つしか開かない）: 応募者ごとに、肖像、名前、年齢、出身派閥、ゼノタイプ、特性、主な技能と情熱、健康上の問題を表示する。情報カード（`Dialog_InfoCard`）ボタンと、採用・拒否の切り替えを置く。
- **MOD 設定**: 加入方式、同時募集の上限、判断期限、恒久敵対派閥を含めるか、子供を許可するか、高額な募集の確認（オン・オフと額）、人数の重み（0〜3人）、各方式の費用と期間、使者の社交補正の係数、再依頼の待ち日数。初期値に戻すボタンを置く。

## 7. 構成

- `GameComponent_Recruitment`: 状態の唯一の保持者。進行中の募集、判断待ち（`ThingOwner<Pawn>`、Deep 保存）、拠点ごとの最後の依頼時刻、通信先を持つ。判断の期限は毎 tick、到着は 250 tick ごとに判定する。
- `RecruitmentMethodDef`: 方式の定義（種類、研究、費用、期間、到着方法、使える場所、到着方法の説明）。
- `FloatMenuOptionProvider_RecruitViaTrader`: 商人の右クリックメニュー。開始処理は JobDriver が行う。
- `RecruitmentCommTarget`（`ICommunicable`）と Harmony パッチ: 通信機の通信先と交渉画面。
- `WorldObjectComp_RecruitmentRequest`（XML パッチで拠点に追加）と `CaravanArrivalAction_RequestRecruitment`: 使者の依頼。
- `Patch_FormCaravan_TrySend`（Harmony）と `Alert_EnvoyCaravanShortOfSilver`: シルバーの警告。
- 純粋ロジック（`Recruitment.Logic` 名前空間、RimWorld に依存しない）: 人数の抽選、社交補正、期間の計算、到着先の選択、支払いの割り当て、再依頼の待ち時間、確認の判定、UI 用キャッシュ。xUnit でテストする。

### 7.1 処理負荷

- メインタブの方式一覧と、訪問中のキャラバンの依頼ボタンの判定は、0.5秒間キャッシュする（`Logic.TimedCache`）。
- 到着時アクションの `StillValid`（移動中に毎回呼ばれる）は、拠点側の軽い判定だけにする。
- 派閥の判定では、許可の確認が要らないときは許可の一覧を作らない。
- 応募者の説明文は、ポーンごとに一度だけ作る。
- シルバー集計と「抽選できる派閥があるか」の判定は、リストを作らず、最初に一致した時点で止める。
- 250 tick ごとの処理で一覧をコピーしない。保持ポーンの回収は、必要なとき（ロード後・配置失敗後）だけ行う。

### 7.2 旧バージョンのセーブ

- 1.0 の使者は、マップから歩いて出て MOD が保持する方式だった。そのようなセーブをロードしたら、最初のチェックで次のように処理する。
  - 不在中の使者は、拠点に戻す。その募集の応募者は、そのまま予定どおり来る。
  - 出発途中だった使者は、費用を返し、出発ジョブを終える。
- 旧方式の JobDef（`Recruitment_DepartAsEnvoy`、`Recruitment_BroadcastRadio`、`Recruitment_BroadcastOrbital`）と JobDriver は、進行中のジョブを含むセーブを読めるように残す。

## 10. 次期バージョンの設計（未実装、2026-10-31 確定）

### 10.1 社交補正をすべての方式に

- 募集を始めた入植者の社交スキル s を使う。
  - キャラバンで募集: 商人と話した入植者。
  - 使者: キャラバンの交渉役。
  - 通信機: 通信機を使った入植者。
- 人数の確率は、「社交0の重み」（初期値 25/25/25/25）と「社交20の重み」（初期値 5/15/50/30）の間を、t = clamp(s, 0, 20) / 20 で直線補間する。例: 社交10なら 15/20/37.5/27.5。
- 両端の重みは MOD 設定で変えられる。使者専用の旧補正（0人の確率 = 35% − 1.5% × s）とその設定は削除する。

### 10.2 派閥への直接募集（通信機の交渉画面）

- Harmony で `FactionDialogMaker.FactionDialogFor` にポストフィックスを当て、交渉画面の最初のページに「入植者の募集を依頼する」を足す。
- 選ぶと、無線放送と軌道通信のどちらにするかを選ぶ。開始の手順は 10.4 の共通の開始画面を使う。
- 費用は、友好度 −10（固定）と、選んだ方式のシルバー。出身派閥は、その派閥に固定する（抽選しない）。
- 依頼できる条件:
  - 敵対していない。
  - 依頼後の友好度が0以上（友好度が10以上）。
  - その派閥が応募者を出せる（3. の条件。帝国は爵位の許可が必要）。
  - その派閥への直接募集で、結果（到着、または0人で失敗）が出ていないものがない。
- 研究・宇宙・同時募集数の条件は、選んだ方式のルールに従う。

### 10.3 シルバーの上乗せ（すべての方式）

| 段階 | 追加費用（方式の費用に対して） | 応募者1人あたりの候補数 |
|---|---|---|
| なし | +0% | 1 |
| 少し | +50% | 2 |
| 多め | +100% | 3 |
| 最大 | +200% | 4 |

- 到着時に、応募者1人ごとに候補を生成し、評価が最も高い1人を採用する。それ以外の候補は破棄する。能力値は書き換えない。
- 評価 = 技能レベルの上位6つの合計 + 情熱（小 +2、大 +4）− 5 × できない仕事の数 − 5 × 健康上の問題の数。係数は MOD 設定で変えられる。
- 特性は評価に含めない。本体のデータには、特性の良し悪しを判別できる情報がないため（`marketValueFactorOffset` が設定されているのは一部のマイナス特性だけ）。
- 応募者が0人なら、上乗せ分も返さない。人数の確率には影響しない。

### 10.4 UI

- **共通の募集開始画面**: すべての方式で同じ画面を使う。表示する内容は次のとおり。
  - 方式、出身派閥（固定か抽選か）、到着方法、期間。
  - 費用の内訳（基本費用、上乗せ、友好度）と、支払い後に残るシルバー。
  - 上乗せの選択。
  - 担当する入植者の社交と、0〜3人の確率。
  - 「開始」と「キャンセル」。
- この画面が確認を兼ねるので、「高額な方式の確認」設定は廃止する。
- **募集タブ**:
  - 進行中の募集: 方式のアイコン、出身、到着先、上乗せの段階、進捗バー。
  - 判断待ち: 残り時間のバーと「確認する」。
  - 方式一覧: 今のマップで使えるかどうかと、使えない理由。
  - 派閥・拠点一覧: 直接依頼ができるか、友好度、結果待ちかどうか、拠点の待ち時間。
